## 1. 板块细化的共同原则

### 1.1 三级信息架构

```text
一级：人生板块       工作 / 知识 / 健康 / 财务 / 生活
二级：专属功能页     每个板块按自己的使用场景拆分
三级：记录与详情     日志、任务、项目、笔记、度量、钱
```

板块不再是一张不断向下堆卡片的长页面。每个板块有一个明确的默认页，具体管理进入二级功能页。

### 1.2 一条信息只录一次

- 原始事实只保留一份，复盘、年度回顾和输出都引用原始数据。
- 不要求用户为了周报、年报或简历重新抄写日常记录。
- 从日常记录中提炼出的成果必须能追溯到项目、记录或度量证据。

### 1.3 模板是功能开关，不是用户模式

- 通用功能默认可用；职业、身份或兴趣相关的专属功能通过模板启用。
- 同一用户可以同时启用多个模板，不需要在“上班族 / 创作者 / 创业者”之间三选一。
- 关闭模板只隐藏入口和专属界面，不删除历史数据。

### 1.4 设计与实施边界

- 五个板块的定位、页面、记录口径、派生关系和边界已经封版。
- UI 方案已经完成 PRD 一致性审查；缺页、重复入口、指标冲突和无法落地的交互已在首版实现前处理。
- 跨板块数据模型、旧数据迁移和公共组件已经统一实现，后续不得回退成每个板块各造一套数据。
- 后续新增模板仍须先完成页面、数据读取、操作、空状态、备份恢复与迁移，再开放入口。

## 2. 工作板块（已封版）

### 2.1 产品定位

工作板块是一个**个人职业系统**：记录当下做过的工作，沉淀项目与成果，形成长期职业档案，并在周报、年终总结、晋升或求职时快速复用。

它不再以商单管理为中心。商单和内容创作是部分用户需要的可选工作模板，不代表“工作”本身。

工作板块要回答三个问题：

1. 我过去具体做过什么？
2. 我产生过哪些可证明的成果和能力？
3. 到周报、年终总结、晋升或求职时，能否直接整理出来？

适用身份包括普通职员、管理者、自由职业者、内容创作者和创业者。同一个人可以同时拥有多段工作经历和多种工作方式。

### 2.2 二级页面

| 页面 | 核心问题 | 主要内容 |
|---|---|---|
| **本周**（默认页） | 我这周最该关心什么？ | 本周重点、本周成果、待跟进、周报草稿、最近工作记录 |
| **工作记录** | 某天具体做过什么？ | 按日期排列的事实时间线；按经历、项目、类型和年份筛选 |
| **项目成果** | 做过什么有边界、有产出的事情？ | 项目背景、目标、角色、行动、结果、证据和关联记录 |
| **周期复盘** | 一周、一月、一年发生了什么？ | 系统归集事实，用户确认成果、判断、学习和下一步 |
| **职业档案** | 长期职业历史是什么？ | 公司、职位、职责、任职时间、关联项目、成果、能力与输出材料 |
| **商单管理**（模板） | 商务合作推进到哪一步？ | 客户、报价、返点、阶段、交付、排期和应收关联 |
| **内容创作**（模板） | 内容从选题到发布表现如何？ | 选题、类型、制作、排期、发布和内容指标 |

### 2.3 “本周”默认页

页面顺序固定为：

1. **本周重点**：用户主动选定的 3–5 件重点，不等于所有待办。
2. **本周成果**：有实际价值、可进入职业档案的结果，不展示任务数量排行榜。
3. **待跟进**：未完成事项、对外承诺和需要继续处理的问题。
4. **本周总结**：系统归集出的周报草稿入口。
5. **最近工作记录**：只展示最近几条，完整记录进入“工作记录”页。

页面不再以本月收入、净利、报价均值、在谈商单数或待回款金额作为通用工作指标。商业金额的主要汇总属于财务板块。

页头主要动作：

```text
模板 · N    记录工作    写本周总结
低频设置    高频记录    周期性主动作
```

### 2.4 核心内容的语义

| 内容 | 定义 | 时间尺度 | 与其他内容的关系 |
|---|---|---|---|
| **工作经历** | 在某个组织、职位或职业身份下工作的连续阶段 | 月到年 | 是项目、记录和成果的长期容器 |
| **工作记录** | 某天实际发生的一件工作事实 | 天 | 可关联经历和项目，可被周报引用 |
| **工作项目** | 有开始、结束、目标和产出的工作事项 | 周到月 | 聚合工作记录，沉淀项目结果 |
| **职业成果** | 能说明个人产生了什么价值的可证明结果 | 周到年 | 从记录或项目结果中提升，不重复抄写 |
| **周期复盘** | 对一个确定时间段的事实归集和人工判断 | 周、月、年 | 引用记录、任务、项目和成果 |
| **职业输出** | 面向简历、述职或面试的选择性呈现 | 按需 | 从经历、项目、成果和复盘中组装，不是另一套源数据 |

工作经历不是项目；“在某公司担任产品经理三年”不能伪装成一个超长项目。职业成果也不是独立重复录入的数据：用户可以从一条记录或项目结果中标记为成果，并补充结果证据。

### 2.5 工作记录

#### 最低录入要求

默认只要求输入一句话。日期自动取今天，当前工作经历自动预选。

#### 可选字段

- 日期
- 类型：进展 / 成果 / 决策 / 问题 / 反馈 / 学习
- 所属工作经历
- 关联项目
- 详细说明
- 数值结果或证据链接

类型、项目和详细说明都不是必填，避免把高频记录变成填表。

#### 保存后的去向

- 立即进入工作记录时间线。
- 自动出现在所属自然周的周报草稿里。
- 关联项目时，同时出现在项目时间线。
- 标记为成果时，进入职业成果候选库。

### 2.6 项目与成果

一个工作项目至少包含：

- 名称
- 所属工作经历
- 开始、结束时间或当前状态
- 背景与目标
- 自己承担的角色
- 关键行动
- 阶段结果与最终结果
- 可量化数据或其他证据
- 关联工作记录

项目结束不等于自动成为职业成果。用户从项目结果中选择真正值得保留的部分，提升为一条或多条职业成果。

职业成果需要回答：

```text
在什么背景下 → 我做了什么 → 产生了什么结果 → 有什么证据
```

没有结果证据的内容仍可保存，但不能伪装成确定的量化成果。

### 2.7 周期复盘

#### 周期口径

- 周报：周一至周日，按本地时区。
- 月报：自然月。
- 年度回顾：自然年。

#### 系统自动归集

- 时间范围内的工作记录
- 完成任务
- 有变化的项目
- 已标记成果
- 决策、问题和反馈类记录

#### 用户人工确认

- 本周期最重要的成果
- 最关键的问题或判断
- 学到了什么
- 下一周期重点

#### 保存规则

- 周报草稿按需生成，不预先制造 52 条空记录。
- 未确认草稿随原始数据变化而更新。
- 用户确认后保存为该周期的复盘快照。
- 下一周期重点可以直接转成任务。
- 月报和年报优先汇总已确认复盘，再补充原始记录。

不设计“工作效率分”“生产力指数”或没有清晰口径的复盘完成百分比。

### 2.8 职业档案与输出

每段工作经历包含：

- 公司、组织或职业身份
- 职位名称
- 任职类型
- 开始和结束时间
- 主要职责
- 关联项目、成果和周期复盘
- 阶段总结

自由职业者或创业者可以把“独立创作者”“自己的公司”作为组织或职业身份，不需要切换产品模式。

职业档案可以按需组装：

- 简历经历
- 晋升述职
- 年终总结
- 面试案例
- 项目案例集

这些输出必须引用已有事实和成果。自动整理可以改变结构和表达，不能凭空发明项目、指标或职责。

### 2.9 可选模板

#### 入口与交互

- 工作页头放置低权重按钮：`模板 · N`。
- 点击后打开模板开关面板。
- 已启用模板在通用二级导航之后增加专属页面。
- 模板可以独立启用和关闭，不互斥。

#### 默认与迁移

- 新用户默认关闭所有专属工作模板。
- 如果升级时检测到已有商单或内容数据，自动启用对应模板，避免用户升级后找不到旧数据。
- 模板开关写入本地设置，并纳入 JSON 备份导入导出。

#### 关闭规则

- 关闭只隐藏专属页面、快捷入口和专属字段。
- 不删除、不改写、不迁移历史数据。
- 重新启用后恢复原有数据和入口。

#### 首批模板

| 模板 | 专属内容 | 跨板块边界 |
|---|---|---|
| **商单管理** | 客户、报价、返点、洽谈/制作/交付阶段、排期、应收关联 | 收入、支出和应收汇总以财务板块为准 |
| **内容创作** | 选题、类型、制作状态、发布日、播放/赞/藏/涨粉、内容复盘 | 代表作可以提升为职业成果；内容表现不混入财务统计 |

### 2.10 现有功能的归位

| 现有功能 | 新位置 |
|---|---|
| Work Board | 改为“本周”默认页 |
| Work log | 扩展为“工作记录”时间线 |
| Projects | 泛化为“项目成果” |
| Pipeline / Quote reference | 进入“商单管理”模板 |
| Content | 进入“内容创作”模板 |
| 本月收入、净利、待回款 | 从通用 Work 首页移出；财务负责汇总，商单页保留项目级关联信息 |
| Work goals / To do | 分别进入本周重点、待跟进和跨板块目标体系 |

### 2.11 明确不做

- 不做多人协作、权限、审批和团队项目管理。
- 不做员工考勤、工时追踪、绩效打分和 HR 系统。
- 不把记录条数、完成任务数直接等同于工作价值。
- 不要求用户每天写完整日报。
- 不生成没有来源证据的简历数据和职业成果。
- 不让商单或内容创作重新成为所有用户的默认工作首页。

### 2.12 产品验收标准

- 普通上班用户不启用任何模板，也能完整使用工作记录、项目、复盘和职业档案。
- 用户用一句话即可完成一条工作记录；其余字段均可后补。
- 一条记录保存后能在当周、关联项目和搜索结果中找到。
- 周报能自动归集该周事实，人工确认后保存为快照。
- 年度回顾可以从已确认复盘、项目和成果中整理，不要求重写全年记录。
- 工作经历、项目和成果能被选择性组装成简历、述职或面试材料。
- 启用模板后出现对应页面和快捷入口；关闭模板后数据仍完整可恢复。
- 商业金额在 Work 和 Finance 之间保持同一数据来源，不出现两套收入数字。

## 3. 知识板块（已封版）

### 3.1 产品定位

知识板块是一个**个人学习系统**：记录学习实际发生的过程，把书籍、课程和技能训练沉淀为自己的理解，并进一步连接实践与输出。

它不是单纯的书单、收藏夹或笔记仓库。知识板块要回答三个问题：

1. 我现在正在学什么，下一步应该继续什么？
2. 我真正理解了什么，还有哪些问题没有想明白？
3. 学到的内容是否形成了可以实践、迁移或输出的能力？

核心链路为：

```text
学习记录 → 笔记与问题 → 洞察 → 实践与输出 → 周期复盘
```

学习资源提供来源，学习记录保存事实，笔记保存思考过程，洞察保存可复用结论。四者不能合并成一种内容。

### 3.2 二级页面

| 页面 | 核心问题 | 主要内容 |
|---|---|---|
| **学习中**（默认页） | 我现在正在学什么，下一步是什么？ | 当前书籍、课程与技能主题、本周学习计划、最近学习记录、待解决问题、学习复盘草稿 |
| **学习记录** | 某天具体学过什么，推进到哪里？ | 按日期排列的学习事实；按资源、主题、类型和年份筛选 |
| **书籍** | 阅读全过程如何管理？ | 想读、在读、暂停、已读、阅读进度、书评和关联内容 |
| **课程与技能** | 系统学习和能力训练进展如何？ | 课程课节进度、技能里程碑、实践证据和关联资源 |
| **笔记与洞察** | 输入最终沉淀成了什么？ | 摘录、理解、问题、洞察及其来源、主题与应用关联 |
| **学习复盘** | 一段时间真正学到了什么？ | 系统归集学习事实，用户确认理解、应用、问题和下一步 |

书籍、课程和技能是不同类型的学习资源，不分别制造互不关联的数据孤岛。学习主题作为跨资源的分类和筛选维度，不单独设置一个空泛的“知识库”页面。

### 3.3 “学习中”默认页

默认页采用“学习中”，不采用“本周”。一本书、一门课程或一个技能训练通常跨越多个自然周，资源状态比周历更稳定；本周计划仍然作为默认页中的行动层。

页面顺序固定为：

1. **当前学习**：正在阅读的书籍、正在进行的课程和当前技能里程碑，支持继续上次位置。
2. **本周学习计划**：用户主动选择的 2–4 项行动，不自动把所有在学资源变成任务。
3. **最近学习记录**：只显示最近几条，完整时间线进入“学习记录”。
4. **待想明白**：仍未解决的问题，而不是普通待办列表。
5. **本周学习复盘**：系统归集出的复盘草稿入口。

页头主要动作：

```text
模板 · N    记录学习    写笔记
低频设置    高频事实    主动沉淀
```

首页不使用“学习力”“知识分”或单纯笔记数量作为总成绩。完成书籍数、学习时长和记录数量只代表活动量，不能直接代表理解质量。

### 3.4 核心内容的语义

| 内容 | 定义 | 示例 | 与其他内容的关系 |
|---|---|---|---|
| **学习资源** | 学习所依赖的来源 | 一本书、一门课程、一份资料 | 被学习记录引用，是笔记和洞察的来源 |
| **学习主题** | 跨资源持续研究的方向 | AI 产品、组织管理、数据系统 | 用于组织资源、记录、笔记和问题 |
| **学习记录** | 某次实际发生的学习事实 | 读到第 248 页、完成第 6 课 | 推进资源状态，可产生笔记或问题 |
| **笔记** | 对来源内容的摘录或个人理解 | 一段摘录、自己的解释 | 可关联资源、主题和学习记录 |
| **问题** | 当前尚未解决的疑问 | 没有历史数据时如何建立评估基线 | 可在后续学习中被回答并转成理解或洞察 |
| **洞察** | 可以迁移、实践或输出的结论 | 离线质量和线上价值必须分开评估 | 可被工作项目、内容创作或其他实践引用 |
| **技能里程碑** | 能证明能力变化的具体行为或结果 | 独立完成一次留存分析 | 作为技能进展证据，不使用主观百分比 |
| **学习复盘** | 对确定周期内学习事实和认知变化的回顾 | 周复盘、月复盘、年度学习回顾 | 引用已有记录、笔记、问题、洞察和里程碑 |

### 3.5 学习记录

#### 最低录入要求

默认只要求填写一句话并选择当前学习资源。日期自动取今天；从资源详情进入时自动带入资源和当前位置。

#### 可选字段

- 日期与时间
- 学习资源
- 学习主题
- 类型：阅读 / 课程 / 练习 / 研究 / 其他
- 本次学习量：页数、课节、时长或自定义描述
- 资源当前位置
- 一句话收获
- 关联笔记或问题

时长不是必填项，不强制用户开启计时器。没有可靠单位时可以只写“完成第 6 课”或“练习了一次”，不制造伪精确数据。

#### 保存后的去向

- 立即进入学习记录时间线。
- 更新关联资源的最近学习时间和明确的当前位置。
- 自动出现在所属自然周的学习复盘草稿中。
- 新增的笔记、问题和洞察与该次学习保持来源关系。

### 3.6 书籍

所有书统一进入知识板块的书库，包括学习阅读和休闲阅读，不把小说等书籍拆到生活板块。通过“学习 / 休闲”等阅读目的，以及主题标签进行区分。

一本书可以经历：

```text
想读 → 在读 → 暂停 → 已读
```

主要字段包括：

- 书名、作者、封面和总页数
- 阅读目的与主题
- 当前页
- 开始、暂停、恢复和读完日期
- 评分与书评
- 关联学习记录、笔记、问题和洞察

#### 阅读进度口径

- `当前页 248 / 616` 表示资源中的绝对位置。
- `本次阅读 32 页` 表示一次学习记录中的增量。
- 当前页不能通过累加历次“读到第几页”得到；本次阅读量也不能覆盖当前位置。
- 只有总页数可靠时才显示完成百分比；未知总页数时只显示当前位置或状态。

读完一本书只是阅读活动完成，不自动表示已经掌握书中知识。书评、理解、洞察和实际应用分别记录，不用一本书的星级替代学习结果。

### 3.7 课程与技能

课程和技能放在同一个二级页面，但使用不同的进展模型。

#### 课程

课程具有明确的章节、课节或模块，可以记录：

- 课程名称、来源、讲师和主题
- 总课数或模块数
- 已完成课节和当前位置
- 开始、暂停和完成日期
- 关联学习记录、笔记、问题和洞察

只有存在明确分母时才显示 `6 / 12 课` 或完成百分比。

#### 技能

技能通常没有客观总量，不显示“数据分析已掌握 63%”之类的主观进度。技能使用可验证的里程碑和实践证据，例如：

- 独立完成一次留存分析
- 用英语完成一次真实沟通
- 完成一次 30 分钟内部分享
- 独立交付一个可运行项目

每个技能可以关联课程、书籍、练习记录、工作项目和已完成里程碑。课程完成不自动等于技能掌握。

### 3.8 笔记、问题与洞察

内容类型固定区分为：

| 类型 | 含义 | 要求 |
|---|---|---|
| **摘录** | 来源中的原文或接近原文的信息 | 必须保留来源；不能伪装成自己的结论 |
| **理解** | 用户用自己的语言重新解释 | 可以不成熟，允许后续修订 |
| **问题** | 当前尚未想明白的内容 | 可以保持未解决，也可以关联后续答案 |
| **洞察** | 可以复用、迁移或实践的结论 | 应说明自己的判断或适用条件 |

每条内容可以关联学习资源、学习主题、学习记录和实际应用。摘录可以继续发展成理解，问题可以被回答，理解可以提升为洞察，但系统不自动替用户完成这种认知判断。

第一版采用列表、筛选和关联，不做知识图谱、复杂双向链接或自动生成概念关系。优先保证来源可追溯、内容容易记录、洞察能够被重新找到。

### 3.9 学习复盘

#### 周期口径

- 周复盘：周一至周日，按本地时区。
- 月复盘：自然月。
- 年度学习回顾：自然年。

#### 系统自动归集

- 学习次数和学习日期
- 推进、暂停或完成的资源
- 明确的页数、课节和时长数据
- 新增的摘录、理解、问题和洞察
- 新完成的技能里程碑
- 仍未解决的问题

#### 用户人工确认

- 本周期真正理解了什么
- 哪些内容应用到了实际场景
- 哪些问题仍未解决
- 下一周期继续学习什么

#### 保存规则

- 复盘按需生成，不预先制造空周报和空月报。
- 未确认草稿随原始数据变化而更新。
- 用户确认后保存为该周期的历史快照。
- 下一周期学习项可以加入“学习中”的本周计划。
- 月度和年度复盘优先汇总已确认的周期复盘，再补充原始记录。

不把学习次数、笔记数量或完成书籍数换算为“知识增长率”或“学习效率分”。

### 3.10 与其他板块的边界

判断依据是内容的目的和结果，而不是学习发生的地点。

| 场景 | 主记录位置 | 跨板块处理 |
|---|---|---|
| 读书、上课、练习、研究 | 知识 | 记录资源进度、理解和问题 |
| 因工作需要学习一门课程 | 知识 | 工作周报可以引用该学习记录，不重复录入课程进度 |
| 把洞察用于一个工作项目 | 工作 | 工作记录结果，并引用知识洞察作为来源 |
| 公司培训或内部分享 | 知识记录学习内容；工作记录职业事件或成果 | 两边通过关联连接，不复制同一事实 |
| 阅读小说或休闲书籍 | 知识 | 用“休闲”阅读目的区分；生活板块不另建重复书单 |
| 将知识整理成公开内容 | 知识保存来源与洞察；工作内容模板保存制作与发布 | 输出表现属于工作，学习来源属于知识 |

工作板块中“学习”类型只用于说明与工作相关的判断、应用或职业事件。书籍、课程、页数、课节和知识笔记仍以知识板块为唯一来源。

### 3.11 可选模板

阅读、课程、技能、笔记和复盘属于通用能力，默认启用，不做成模板。特殊学习方法通过模板扩展。

#### 首批预留模板

| 模板 | 专属内容 | 不改变的通用数据 |
|---|---|---|
| **考证备考** | 考试日期、科目、题库练习、模考结果 | 课程、记录、笔记和复盘仍使用通用模型 |
| **语言学习** | 词汇、听说读写练习、考试目标 | 学习记录和技能里程碑仍是来源 |
| **专题研究** | 研究问题、资料清单、阶段结论 | 资源、问题、洞察和输出仍是通用内容 |

模板沿用共同规则：点击页头 `模板 · N` 启用或关闭；关闭只隐藏专属入口和字段，不删除历史数据。首版实施时可以只建立模板机制，不必同时做完全部预留模板。

### 3.12 现有功能的归位

| 现有功能 | 新位置或调整 |
|---|---|
| Reading now | 进入“学习中”的当前学习，并可打开书籍详情 |
| Want to read / Finished | 合并进“书籍”，用状态筛选，不继续做分散卡片 |
| Recent notes | 进入“笔记与洞察”，区分摘录、理解、问题和洞察 |
| Courses & skills | 进入“课程与技能”，课程与技能采用不同进展模型 |
| Knowledge goals | 本周行动进入“学习中”；长期方向作为年度学习方向或主题 |
| 当前页数与阅读页数统计 | 分离绝对当前位置与单次阅读增量，统一实施时审查旧数据口径 |
| 页面顶部汇总数字 | 保留可解释的活动事实，不将数量包装为学习质量 |

### 3.13 明确不做

- 不做收藏一切网页、文件和链接的通用资料库。
- 不做知识图谱、复杂双向链接和自动关系图。
- 不用 AI 自动生成的摘要替代用户自己的理解。
- 不做没有客观分母的技能掌握百分比。
- 不把时长、页数、笔记数或读完书籍数直接等同于知识价值。
- 不强制计时，不要求每次学习填写完整表单。
- 不把同一次学习分别复制到知识和工作两套记录中。
- 不因关闭模板而删除考证、语言或研究数据。

### 3.14 产品验收标准

- 用户打开知识板块即可看见当前学习资源、本周计划和待解决问题。
- 用户用一句话并选择资源即可完成一条学习记录，其余字段均可后补。
- 书籍当前页与单次阅读量分别保存，不能因多次记录造成进度累加错误。
- 课程只在存在明确课节总量时显示进度；技能只通过里程碑和证据呈现变化。
- 摘录、理解、问题和洞察具有明确类型与来源，可以筛选和互相关联。
- 学习复盘能自动归集周期事实，人工确认后保存为历史快照。
- 学习洞察可以被工作项目或内容输出引用，但不复制成另一条源数据。
- 所有书籍使用同一书库，并能按“学习 / 休闲”等阅读目的筛选。
- 启用模板后出现对应专属入口；关闭模板后历史数据仍完整可恢复。

## 4. 健康板块（已封版）

### 4.1 产品定位

健康板块是一个**个人健康管理系统**：观察身体指标的长期变化，保持适合自己的运动节奏，保存重要健康历史，并及时处理真正需要关注的事项。

它不是每日打卡器、专业运动软件或医疗诊断系统。健康板块要回答四个问题：

1. 我现在的身体状态和近期趋势是什么？
2. 我的运动是否保持了自己设定的节奏？
3. 过去发生过哪些重要的症状、受伤、就医、体检或用药变化？
4. 现在还有哪些健康事项需要观察、复查或处理？

核心链路为：

```text
运动事件 + 身体读数 + 健康事件 → 当前状态与健康档案 → 周期复盘
```

系统只整理用户记录的事实，不自动推断疾病、诊断、正常范围或治疗方案。

### 4.2 二级页面

| 页面 | 核心问题 | 主要内容 |
|---|---|---|
| **当前状态**（默认页） | 我现在最需要关注什么？ | 最新身体指标、趋势曲线、本周运动节奏、待处理事项、最近健康事件、复盘草稿 |
| **运动训练** | 最近练了什么，节奏是否正常？ | 运动记录、周目标、运动构成、训练周期和训练目标 |
| **身体指标** | 身体数据如何变化？ | 体重、体脂、血压、自定义指标的最新值、历史读数和趋势 |
| **健康记录** | 过去发生过哪些重要健康事件？ | 症状、受伤、就医、体检、疫苗、用药变化的时间线 |
| **健康档案** | 当前有哪些仍然有效的健康信息？ | 当前用药、已确认过敏、长期情况、待复查事项和体检历史 |
| **健康复盘** | 一段时间的身体变化是什么？ | 系统归集运动、读数和事件，用户确认感受、关注事项和下一步 |

### 4.3 “当前状态”默认页

默认页采用“当前状态”，不采用“本周”。运动适合按周观察，身体指标、症状、体检与用药分别跨越周、月和年；默认页需要把这些不同时间尺度压缩成当前可行动的信息。

页面顺序固定为：

1. **当前身体指标**：每个已启用指标的最新值、记录日期和明确时间窗内的变化。
2. **主要趋势曲线**：默认显示用户选择的主指标，不一次堆满所有曲线。
3. **本周运动节奏**：本周实际运动与用户设定目标的对比；没有目标时只展示事实。
4. **需要处理**：待预约体检、待复查、持续观察中的健康事件和已到期读数。
5. **最近健康记录**：只显示最近的重要事件，完整历史进入“健康记录”。
6. **健康复盘**：当前周期的复盘草稿入口。

页头主要动作：

```text
模板 · N    记录运动    健康记录
低频设置    高频事件    重要健康事实
```

首页不展示缺乏行动意义的历史累计运动总次数，不设计综合“健康分”“身体年龄”或没有可解释口径的风险颜色。

### 4.4 核心内容的语义

| 内容 | 定义 | 示例 | 正确的统计方式 |
|---|---|---|---|
| **运动事件** | 一次实际发生的身体活动 | 跑步 5 km、力量训练 45 分钟 | 次数、距离、时长等明确单位可以按周期累计 |
| **身体读数** | 某个时间点的一次测量 | 体重 71.2 kg、血压 126/82 | 不可累加，只看最新值、变化和趋势 |
| **健康事件** | 一个值得保留的身体或医疗事实 | 右膝不适、体检、牙科复诊、开始用药 | 按时间保存和筛选，不进入运动统计 |
| **训练周期** | 有开始、结束和训练目的的一段计划 | 8 周基础力量、半程马拉松备赛 | 聚合关联运动记录，展示周期状态和计划完成情况 |
| **健康档案项** | 当前仍然有效的个人健康信息 | 当前用药、已确认过敏、长期情况 | 引用或确认历史事件的当前状态，不重新抄写一份历史 |
| **健康任务** | 将来需要完成的一次行动 | 预约体检、下月复查 | 完成后关闭；结果另存为对应健康事件 |
| **健康复盘** | 对确定周期内身体事实和主观感受的回顾 | 周、月、年度健康回顾 | 引用运动、读数、事件和任务，不生成诊断结论 |

运动事件、身体读数和健康事件必须显式区分。没有选择领域的普通健康日志不能再被系统自动猜测为运动，否则症状和就医记录会污染运动次数、距离和连续周数。

### 4.5 运动记录与训练周期

#### 最低录入要求

一次运动默认只要求选择运动类型，日期自动取今天。

#### 可选字段

- 日期和时间
- 运动类型
- 时长
- 距离
- 次数或组数
- 主观强度
- 简短感受
- 关联训练周期

只有用户实际填写且单位明确的数值才参与累计。跑步距离、力量训练时长和训练次数不能混成一个“运动量”总分。

#### 运动节奏与目标

支持的目标示例：

- 每周运动 3 次
- 每周完成 2 次力量训练
- 全年跑步 300 km
- 某训练周期内完成指定次数的训练

目标进度从运动记录计算，不单独保存打卡结果。连续性按“连续活跃周”计算，不要求每天运动；正常休息日不能被产品判定为失败或断签。

#### 训练周期

训练周期用于有明确边界的计划，例如 8 周力量训练或比赛备赛，主要包含：

- 名称和训练目的
- 开始、结束时间
- 状态：计划中 / 进行中 / 已完成 / 已暂停
- 周节奏或明确目标
- 关联运动记录
- 周期总结

普通运动用户不需要创建训练周期。训练周期的产品状态不复用内容项目的“发布”等词汇。

### 4.6 身体指标

身体指标分为：

- **单值指标**：体重、体脂、腰围、静息心率等。
- **组合指标**：血压等需要同时保存多个相关值的读数。
- **自定义指标**：用户自己命名、设置单位和记录频率。
- **导入指标**：未来由可穿戴设备或健康数据源导入的高频数据。

每条读数至少包含指标、日期和数值，可选记录测量条件与备注。页面展示：

- 最新值和记录日期
- 明确时间窗内的变化值
- 可切换时间范围的趋势曲线
- 用户自己设定的记录频率和个人目标
- 历史读数列表

#### 方向与目标口径

- 身体指标默认只描述变化，不自动判断“上升是好”或“下降是好”。
- 体重和体脂不能默认设成“越低越好”。
- 用户可以为某项指标设置个人目标值或目标区间，目标进度按该目标计算。
- 系统不硬编码医疗正常范围，不根据读数自动显示诊断、危险级别或治疗建议。
- 没有可靠分母或目标时不显示完成百分比。

统一实施时需要审查现有 `weight`、`bodyfat` 默认向下为好的逻辑，并为血压等组合读数补充正确的数据形状。

### 4.7 健康记录

健康记录保存低频但重要、以后需要查找的事实，类型包括：

- 症状
- 受伤
- 就医
- 体检或检查
- 疫苗
- 用药开始、停止或调整
- 其他重要健康事件

#### 最低录入要求

默认只要求填写一句话，日期自动取今天。

#### 可选字段

- 类型
- 开始日期与结束日期
- 状态：观察中 / 已恢复 / 需复查 / 已完成
- 身体部位
- 影响或主观感受
- 医生已经给出的结论
- 用药变化
- 下次复查日期
- 关联运动记录、身体读数或健康任务
- 报告或资料的本地引用

“医生已经给出的结论”和“用户自己的描述”必须能够区分。系统不得根据症状文本自动生成诊断，也不得把一次异常读数自动升级为疾病记录。

### 4.8 健康档案

健康档案不是另一套重复录入的数据，而是从历史记录中整理出的**当前有效状态**。

主要内容包括：

- 当前使用中的药物或补充剂
- 用户确认的过敏信息
- 用户确认的长期健康情况
- 观察中、待复查或尚未结束的健康事件
- 待预约和待完成事项
- 历年体检与检查历史

档案项必须能够追溯到用户确认或一条健康记录。结束用药、完成复查或健康事件恢复后，档案更新当前状态，原始历史仍然保留。

档案只用于个人记录和回顾，不声明其完整性，也不替代医院病历、处方或专业医疗建议。

### 4.9 提醒与待处理事项

健康提醒只在存在明确依据时出现：

- 某身体指标超过用户设定的记录周期仍未记录
- 本周运动与用户设定的节奏有差距
- 某健康事件仍在观察中并到达用户设定的复查日期
- 已记录的体检、牙科或其他复查日期临近
- 用户创建的健康任务到期

系统不根据通用医学规则自动提醒用户增减药物、改变剂量或判断是否患病。紧急程度不由产品自行推断。

### 4.10 健康复盘

#### 周期口径

- 周复盘：周一至周日，适合观察运动节奏和近期身体感受。
- 月复盘：自然月，适合观察身体指标趋势与健康事件。
- 年度健康回顾：自然年，适合回顾长期趋势、体检和未完成事项。

#### 系统自动归集

- 运动次数、明确的距离和时长
- 运动类型分布与连续活跃周数
- 新增身体读数及时间窗内变化
- 新增、恢复或仍在观察中的健康事件
- 已完成和待处理的体检、复查与健康任务
- 训练周期的变化

#### 用户人工确认

- 本周期身体感受有什么变化
- 哪些事项需要继续关注
- 运动和恢复节奏是否需要调整
- 下一周期准备采取什么行动

#### 保存规则

- 复盘按需生成，不预先制造空记录。
- 未确认草稿随原始数据变化而更新。
- 用户确认后保存为该周期的历史快照。
- 下一步可以创建健康任务或调整个人运动计划。
- 复盘不自动提供诊断、风险结论和治疗建议。

### 4.11 睡眠、步数、心率与饮食

- 睡眠、步数和连续心率属于设备产生的高频数据，第一版不要求用户每天手动录入。
- 未来接入设备数据时以只读导入为主，并明确显示来源、时间范围和缺失日期。
- 某次或持续性的睡眠问题可以作为健康事件记录，但不因此建立强制每日睡眠表。
- 精确饮食、热量和营养素记录摩擦高，不作为所有用户默认功能。
- 饮食管理放入可选模板；没有启用模板时，重要饮食相关情况仍可作为健康事件记录。

### 4.12 可选模板

当前状态、通用运动、身体指标、健康记录、健康档案和复盘属于核心能力，默认启用。专业记录需求通过模板扩展。

| 模板 | 专属内容 | 不改变的通用数据 |

| **跑步训练** | 配速、分段、比赛、跑量计划 | 每次跑步仍是一条运动记录 |

### 4.13 与其他板块的边界

| 场景 | 主记录位置 | 跨板块处理 |

### 4.15 明确不做

- 不做疾病诊断、药物推荐、剂量建议和治疗方案。
- 不硬编码通用医学正常范围并据此制造红色警报。
- 不把体重或体脂默认定义为越低越好。
- 不生成综合健康分、身体年龄或无法解释的风险分数。
- 不要求用户每天打卡、每天称重或每天填写身体问卷。
- 不手动维护步数、连续心率和详细睡眠数据。
- 不把所有运动压成一种无法解释的“运动量”。
- 不把症状、就医和体检记录计入运动次数。
- 不在健康板块重复记录医疗或健身支出。
- 不让关闭模板删除敏感健康历史。

### 4.16 产品验收标准

- 用户打开健康板块即可看到最新身体指标、主要趋势、本周运动节奏和待处理事项。
- 一次运动最少只需选择运动类型即可保存，其余字段均可后补。
- 运动事件、身体读数和健康事件使用不同数据口径，任何统计都不能混用。
- 身体读数不能累加；趋势默认中性，只有个人目标可以定义目标方向或区间。
- 健康记录能覆盖症状、受伤、就医、体检和用药变化，并保留来源与状态。
- 健康档案可以从记录中呈现当前用药、过敏、长期情况和待复查事项，不要求重复录入。
- 连续性按活跃周计算，休息日不会造成“断签”。
- 睡眠、步数和连续心率未接入设备前不要求手动维护。
- 健康复盘能够自动归集事实，人工确认后保存为历史快照，但不生成医疗结论。
- 启用模板后出现专业字段和页面；关闭模板后历史数据仍完整可恢复。

## 5. 财务板块（已封版）

### 5.1 产品定位

财务板块是一个**个人财务管理系统**：看清实际现金流，建立资产负债视图，管理投资理财，并把每月发生的金额转化为下一步财务决策。

它不再等同于商单统计页，也不能只用一条总净值曲线代表个人财务。财务板块始终区分三套口径：

```text
现金流：一段时间实际进出多少钱
资产负债：某个时间点拥有什么、欠多少钱
投资理财：投资账户价值、投入、配置与决策
```

三者可以在默认页汇总，但底层不能混算。内容播放、点赞、收藏和发布节奏不属于财务数据，继续由工作板块的内容创作能力负责。

### 5.2 二级页面

| 页面 | 核心问题 | 主要内容 |
|---|---|---|
| **本月**（默认页） | 这个月的财务状态怎么样？ | 实际收入、实际支出、结余、最近资产状态、待收待付和复盘草稿 |
| **收支流水** | 钱实际从哪里来、去了哪里？ | 收入、支出、退款、转账、应收应付、固定收支和分类明细 |
| **资产负债** | 现在真正拥有多少？ | 现金账户、投资账户、其他资产、信用卡、贷款、余额快照和净资产趋势 |
| **投资理财** | 投资资产如何变化和配置？ | 投资账户、估值快照、净投入、价值变化、资产配置、投资记录与计划 |
| **预算计划** | 接下来准备怎样安排钱？ | 分类预算、固定事项、未来账单、应急资金和财务目标 |
| **财务复盘** | 一段时间发生了什么，下一步怎么调整？ | 月度与年度现金流、资产、投资和财务决策快照 |

### 5.3 “本月”默认页

默认页采用“本月”，不采用泛化的“总览”。现金流最适合按自然月观察；资产和投资在此只显示最近一次状态，详细管理进入专属页面。

页面顺序固定为：

1. **本月实际收入**：按到账日期确认的收入。
2. **本月实际支出**：按付款日期确认的支出，不含账户间转账。
3. **本月结余**：实际收入减实际支出。
4. **本月现金流趋势**：收入与支出分开呈现，不压成一个模糊总分。
5. **资产状态**：最近一次资产、负债、净资产和投资资产快照及更新时间。
6. **需要处理**：待回款、待付款、到期账单和需要更新的账户。
7. **最近流水与财务复盘**：只显示最近几条和本月草稿入口。

页头主要动作：

```text
账本范围    记收支    更新资产
查看口径    高频流水   周期性快照
```

本月页不把报价、待回款和实际到账收入相加，也不把投资账户转入金额当作消费支出。

### 5.4 核心内容的语义

| 内容 | 定义 | 示例 | 统计口径 |
|---|---|---|---|
| **实际收入** | 已经到账的一笔现金流入 | 工资到账、商单回款、利息到账 | 按到账日期计入周期收入 |
| **实际支出** | 已经付出的一笔现金流出 | 房租、餐饮、软件订阅 | 按付款日期计入周期支出 |
| **退款** | 对原收入或支出的反向更正 | 商品退款、退还客户款项 | 关联原流水并冲减对应口径，不伪装成新收入或新支出 |
| **转账** | 自己账户之间的资金移动 | 银行卡还信用卡、转入投资账户 | 不计入收入和支出，只改变账户余额或资产构成 |
| **应收 / 应付** | 已确定但尚未实际到账或付款的金额 | 商单尾款、信用卡账单 | 单独展示；结清后产生或关联实际流水 |
| **账户** | 保存资金或负债的容器 | 银行卡、投资账户、信用卡、贷款 | 账户余额按时间点保存，不跨日期累加 |
| **余额快照** | 某个日期的账户余额 | 8月1日银行卡余额 ¥82,600 | 用于计算当期资产、负债和净资产 |
| **投资记录** | 投资资金、资产或决策发生的事件 | 投入、取出、买入、卖出、分红、费用 | 根据类型影响账户、现金流或投资分析，不能一律当收支 |
| **预算** | 对未来周期的金额计划 | 8月餐饮预算 ¥4,500 | 实际金额只来自流水，预算本身不产生支出 |
| **财务复盘** | 对周期内现金流、资产和投资的回顾 | 月度、年度财务复盘 | 引用事实并保存决策快照 |

### 5.5 收支流水

一次流水至少需要：

- 类型：收入 / 支出 / 退款 / 转账
- 金额
- 日期

可选字段包括：

- 分类
- 来源账户与目标账户
- 所属账本
- 关联工作项目、生活项目或应收应付事项
- 备注

#### 关键规则

- 转账必须同时指定来源和目标账户，不进入收入、支出和结余。
- 信用卡消费在消费发生时记支出；之后信用卡还款只减少负债，不再次记支出。
- 转入投资账户属于转账；买入和卖出属于投资资产形态变化。
- 分红、利息和投资费用可以形成对应的投资收入或支出，但必须与投资记录关联，避免重复录入。
- 固定收支可以从历史重复模式提出建议，必须经用户确认后才成为未来计划。

### 5.6 商单、应收与收入确认

工作板块负责商单过程，财务板块负责金额状态。两者共享来源但语义不同：

```text
报价 / 已确认金额 → 预期金额，不是实际收入
完成交付 → 可以形成应收
实际到账 → 按到账日形成收入流水
```

- 商单报价不计入实际收入。
- 洽谈中和制作中的商单只提供预测，不进入现金流。
- 已交付未回款金额进入应收。
- 支持一次商单分多次回款；每次到账分别形成流水，并减少应收余额。
- 项目成本按实际付款日期进入支出，同时保留项目关联。

这会替代当前按发布月和项目报价推导收入的口径。统一实施时必须同时调整本月收入、年度收入、净额、目标和应收视图，不能只改其中一个数字。

旧数据缺少真实到账日期时不能凭空猜测。迁移方案需要区分“历史估算收入”和“已确认实际收入”，由用户逐步确认。

### 5.7 资产、负债与净资产

账户类型至少包括：

- 现金和银行卡
- 投资账户
- 应收资产
- 房产或其他资产
- 信用卡
- 贷款及其他负债

净资产固定使用：

```text
净资产 = 资产合计 − 负债合计
```

每次更新保存各账户在同一日期的余额快照。不同日期的余额不可累加；趋势使用每个周期最新或用户确认的快照。

现有单一“总净值”读数可以保留为历史总额快照。统一实施后，详细用户的净资产优先从账户快照计算，不再要求同时维护账户余额和另一条总净值造成两套答案。

### 5.8 投资理财

投资理财属于财务核心能力，不做成可选模板。

#### 核心内容

- 投资账户与最近估值日期
- 账户价值历史快照
- 按资产类别的当前配置
- 投入和取出
- 买入和卖出记录
- 分红、利息、费用和税费
- 定投与再平衡计划
- 投资判断、交易理由和周期复盘

#### 投入与价值变化

```text
净投入 = 转入投资账户 − 转出投资账户

价值变化 = 期末投资价值 − 期初投资价值 − 净投入
```

“价值变化”表示剔除外部资金流后的金额变化，不在资金发生时间不完整时自动包装成精确收益率、年化收益率或超额收益。

- 投资账户估值必须显示更新时间。
- 资产配置按最近一次估值快照计算。
- 只有数据和计算方法完整时才显示收益率，并明确计算口径。
- 用户可以保存投资计划和判断，但产品不提供证券推荐、买卖建议或收益承诺。

第一版以账户和资产类别为核心，不依赖实时行情。详细证券持仓与成本价可以通过模板扩展；没有行情来源时必须明确其数据可能滞后。

### 5.9 预算与财务目标

预算是计划，实际金额只来自流水。

支持：

- 月度总支出预算
- 收支分类预算
- 固定收入与固定开销计划
- 未来 30 天确定账单
- 应急资金目标
- 年度储蓄目标
- 年度投资净投入目标
- 净资产目标

预算使用自然月。预算进度从实际支出计算，转账不占用支出预算；退款按原分类冲减实际金额。

财务目标不能手动拖动进度：现金流目标从流水计算，资产目标从余额快照计算，投资投入目标从投资账户转入和转出计算。

### 5.10 账本范围与可选模板

新用户默认使用“个人账本”。经营财务通过模板启用，默认不与个人财务合并。

| 范围或模板 | 主要内容 | 默认规则 |
|---|---|---|
| **个人账本**（核心） | 工资、生活收支、个人账户、投资和个人负债 | 新用户默认启用 |
| **经营财务**（模板） | 商单回款、项目成本、投流、经营开销、应收与税务事项 | 检测到已有商单和经营数据时自动启用 |
| **详细持仓**（模板） | 证券、数量、成本价和逐笔交易 | 默认关闭；不承诺实时行情 |
| **多币种账户**（模板） | 账户原币余额、估值币种和汇率快照 | 默认关闭；汇率必须有日期和来源 |
| **房产与贷款**（模板） | 房产估值、贷款余额和还款计划 | 默认关闭 |

用户可以切换个人账本、经营账本或主动查看全部账本。系统不能默认把公司经营现金流并入个人收入和净资产。

模板沿用共同规则：关闭只隐藏专属入口和字段，不删除历史数据。

### 5.11 财务复盘

#### 周期口径

- 月度复盘：自然月。
- 年度复盘：自然年。

#### 系统自动归集

- 实际收入、支出、结余与储蓄率
- 分类支出与预算执行
- 资产、负债和净资产变化
- 投资净投入、价值变化和资产配置变化
- 新增、结清和逾期的应收应付
- 固定收支与未来确定事项

#### 用户人工确认

- 本周期发生了哪些异常或一次性变化
- 哪些预算需要调整
- 哪些应收应付需要处理
- 投资计划是否继续或需要重新判断
- 下一周期采取什么行动

#### 保存规则

- 复盘按需生成，不预先制造空记录。
- 未确认草稿随原始数据变化而更新。
- 用户确认后保存为该周期快照，不因以后补录而静默改写。
- 下一步可以生成财务任务、预算或投资计划。

### 5.12 与其他板块的边界

| 场景 | 主记录位置 | 跨板块处理 |
|---|---|---|
| 工资、生活支出、账户余额和投资 | 财务 | 作为金额与资产状态的唯一来源 |
| 商单报价、制作和交付过程 | 工作 | 工作保存过程；财务引用应收、回款和成本 |
| 内容播放、点赞、收藏和发布节奏 | 工作的内容创作能力 | 不进入财务统计；财务只保存金额 |
| 学习投资知识和形成投资观点 | 知识 | 实际投资计划、账户和交易结果进入财务 |
| 医疗、旅行、娱乐等支出 | 财务 | 健康或生活项目可以引用支出，不另记一笔钱 |

### 5.13 现有功能的归位

| 现有功能 | 新位置或调整 |
|---|---|
| Cash flow | 进入经营财务模板；个人收支使用新的通用流水口径 |
| Revenue / Cost / Net | 按真实到账和付款日期重算，并随账本范围切换 |
| Receivables | 保留为经营账本的待收视图；到账后关联实际收入流水 |
| Overheads | 进入经营账本的固定经营支出，并与个人固定支出分开 |
| Assets | 扩展为“资产负债”，从单一总净值升级为账户余额快照 |
| Net worth Metric | 保留历史快照；以后优先从资产与负债账户计算 |
| 年度收入累计 | 按实际到账日期和账本范围计算，不再按项目发布时间推导 |
| 投资交易 | 进入新的“投资理财”页面，区分转账、交易、收益和费用 |
| Stats 中的内容指标 | 移回工作板块内容分析，不与财务金额混排 |

### 5.14 明确不做

- 不把报价、预测收入和应收款计入实际收入。
- 不把账户间转账、信用卡还款和投资转入当作支出。
- 不把不同日期的账户余额相加。
- 不要求同时维护账户余额和另一条无法对账的总净值。
- 不在资金时间数据不完整时生成精确收益率或年化收益率。
- 不提供证券推荐、买卖建议和收益承诺。
- 不假装拥有实时行情；所有手动估值必须显示更新时间。
- 不默认混合个人账本和经营账本。
- 不把内容播放与互动指标放进财务板块。
- 不因关闭模板删除流水、账户或投资历史。

### 5.15 产品验收标准

- 用户打开财务板块即可看到本月实际收入、实际支出、结余、最近资产状态和待处理事项。
- 收入、支出、退款、转账和应收应付具有不同口径，统计不会混用。
- 商单报价和待回款不计入实际收入；分次到账可以分次确认收入并减少应收。
- 信用卡消费只记一次支出，还款不会造成重复支出。
- 资产和负债按同一日期的余额快照计算净资产，并能形成历史趋势。
- 投资页面能展示账户价值、净投入、价值变化和资产配置，并明确估值日期。
- 预算实际金额来自流水，财务目标来自真实现金流或账户余额。
- 个人账本与经营账本默认分开；已有商单数据升级后仍能找到并自动启用经营模板。
- 财务复盘能自动归集现金流、资产和投资事实，确认后保存历史快照。
- 内容表现指标不会重新混入财务页面。

## 6. 生活板块（已封版）

### 6.1 产品定位

生活板块是一个**个人体验与关系系统**：把以后想做的事转成真实计划，记录已经发生的体验与相聚，并形成能够回看的个人生活历史。

它不是其他四个板块装不下之后的杂物箱，也不是用旅行次数、娱乐数量和联系人数量评价生活质量的打卡页面。

生活板块要回答四个问题：

1. 接下来一段时间，我想主动安排怎样的生活？
2. 我有哪些愿望已经准备转成计划？
3. 最近经历了什么、和谁产生了联系？
4. 回看一个月或一年时，哪些生活真正值得记住？

核心链路为：

```text
愿望 → 近期选择 → 计划 → 体验或相聚 → 生活回忆 → 月度 / 年度回顾
```

### 6.2 二级页面

| 页面 | 核心问题 | 主要内容 |
|---|---|---|
| **近期**（默认页） | 接下来准备怎样生活？ | 未来 30 天安排、重要日期、选入近期的愿望、想联系的人、最近体验和回顾草稿 |
| **想做的事** | 以后想体验或完成什么？ | 想做、近期选择、计划中、已完成和已搁置的愿望 |
| **旅行** | 想去哪里，旅行如何准备和回顾？ | 想去、计划、行程、同行人、过程记录、游记和旅行历史 |
| **体验记录** | 最近看过、去过和体验过什么？ | 影视、演出、展览、餐饮、活动和日常体验及短评 |
| **人际** | 关心的人最近怎么样？ | 人物档案、联系记录、重要日期和用户自定义的联系节奏 |
| **生活回顾** | 一段时间有哪些生活值得记住？ | 月度和年度生活事实、回忆、关系变化和下一阶段选择 |

### 6.3 “近期”默认页

默认页采用滚动 30 天的“近期”，不采用自然周或泛化总览。生活中的旅行、活动、生日和相聚通常跨周安排，30 天既能看到即将发生的事，也不会把未来一年全部压到首屏。

页面顺序固定为：

1. **未来 30 天**：已经确定的旅行、活动、生日、纪念日和其他日期。
2. **本月想主动发生**：用户从愿望清单中主动选出的 2–4 件事，不等于所有愿望。
3. **想联系的人**：只显示为具体人物设置了联系节奏、当前已到期的人。
4. **最近留下的生活**：最近已经发生的体验和相聚，不与待办混在一起。
5. **生活回顾**：本月回顾草稿入口。

页头主要动作：

```text
模板 · N    添加计划    记录生活
低频设置    未来安排    已发生体验
```

首页不再以旅行次数、看过数量、联系人数量和愿望数量作为主体，不生成“生活充实度”“关系健康分”或愿望完成率。

### 6.4 核心内容的语义

| 内容 | 定义 | 示例 | 与其他内容的关系 |
|---|---|---|---|
| **愿望** | 以后想做，但尚未承诺时间的事 | 去青海湖、学会冲浪 | 可以被选入近期，之后转成计划、旅行或体验 |
| **近期选择** | 用户决定在当前月份主动安排的愿望 | 8月去看一次现场演出 | 不是完整项目，可以继续确定日期和下一步 |
| **生活计划** | 已经有时间、下一步或同行人的未来事项 | 8月16日去看展 | 完成后连接实际体验，不复制一份结果 |
| **旅行** | 有明确地点、时间范围和过程的一段生活项目 | 大理四天、苏州周末 | 聚合行程、同行人、记录和游记，费用引用财务 |
| **体验记录** | 一次已经发生、值得留下的生活体验 | 一部电影、一次展览、一次散步 | 可以关联人物、地点、旅行和原计划 |
| **人物** | 一个稳定的真实关系对象 | 家人、朋友、伴侣 | 被联系记录、旅行、体验和重要日期引用 |
| **联系记录** | 与一个或多个人发生的一次互动事实 | 见面、通话、一起吃饭 | 更新最近联系时间，不自动评价关系质量 |
| **重要日期** | 与人物或关系相关、可重复的日期 | 生日、纪念日 | 每年滚动提醒，来源不会在完成提醒后消失 |
| **生活回顾** | 对一段时间内体验、关系和愿望变化的回顾 | 月度、年度回顾 | 引用已有事实并保存个人判断快照 |

### 6.5 想做的事

愿望不等于任务。状态固定区分为：

```text
想做 → 选入近期 → 计划中 → 已完成
                  ↘ 已搁置
```

#### 最低录入要求

默认只需要一句话，不要求日期。

#### 可选字段

- 类型：旅行 / 体验 / 家庭 / 兴趣 / 其他
- 想做的原因
- 适合的季节或时间范围
- 想和谁一起
- 地点
- 预计所需时间
- 下一步

愿望只有在用户主动选择后才进入近期；有了明确日期、同行人或下一步后才成为计划。旅行愿望可以转为旅行，单次体验可以转为生活计划。

完成后保留原愿望与实际记录的关联，不额外复制一条“完成任务”。愿望不会因长时间未完成而变成逾期，也不计算年度愿望完成率。

### 6.6 旅行

一次旅行使用生活语义的状态：

```text
想去 → 计划中 → 进行中 → 已完成
                    ↘ 已取消
```

主要内容包括：

- 地点和想去的原因
- 开始与结束时间
- 同行人
- 行程安排和预订事项
- 旅行过程记录
- 游记、短评和最值得记住的内容
- 关联愿望、体验和人物
- 财务预算与实际支出的引用

旅行费用只在财务板块保存一次。旅行页可以展示预算与支出汇总，但金额必须引用财务流水，不能在游记和旅行详情中另存第二套实际金额。

旅行中的跑步、骑行和徒步，如果需要进入运动统计，由健康板块保存运动事实；生活板块只保存旅行体验和行程，两者建立关联。

### 6.7 体验记录

体验类型包括：

- 影视
- 演出
- 展览
- 餐饮
- 活动
- 日常生活体验

#### 最低录入要求

默认只需要填写一句话，日期自动取今天。

#### 可选字段

- 类型
- 地点
- 同行人
- 简短感受
- 评分
- 详细记录
- 关联愿望、计划或旅行

评分只属于单次体验，不汇总成生活质量分。小说和其他书籍继续统一进入知识书库，不因阅读目的为休闲就在生活板块再建一份“看过”。

第一版不做影视资料库、自动抓取海报、地点点评平台或照片管理器。允许保存必要的本地引用，但不把大量媒体文件塞进 JSON 备份。

### 6.8 人际

人物必须是稳定实体，不能继续通过生活日志的自由文本标题识别人名。否则“老王”“王哥”“王老师”会被系统当成三个人。

#### 人物档案

- 姓名和关系
- 认识背景
- 重要备注
- 最近联系时间
- 用户自己设置的联系节奏
- 生日和其他重要日期
- 关联联系记录、旅行和体验

#### 联系记录

一次联系至少选择人物，日期自动取今天；可选记录方式、地点、一起聊了什么、下次想跟进什么，以及关联的旅行或体验。

#### 提醒规则

- 只有用户主动为具体人物设置联系节奏，才产生“该联系了”的提醒。
- 没有设置频率的人只显示最近联系时间，不显示逾期或警告。
- 取消全局统一的 60 天未联系阈值。
- 一次联系只更新事实，不增加亲密度分数。
- 不生成联系人排行榜、关系健康分或社交活跃度。

生日和纪念日属于人物或关系的稳定日期。完成当年提醒后只推进到下一年，不能删除原始日期。

### 6.9 生活回顾

#### 周期口径

- 月度生活回顾：自然月。
- 年度生活回顾：自然年。

生活不强制每周复盘；需要周视角的已确定事项由“近期”和全局日历负责。

#### 系统自动归集

- 完成和取消的旅行
- 新增的体验记录
- 联系或相聚过的人
- 完成、转成计划和搁置的愿望
- 重要日期和近期计划的变化

#### 用户人工确认

- 本周期最值得记住的生活
- 哪些关系发生了变化
- 哪些安排真正带来满足或意义
- 哪些愿望不再重要
- 下一阶段想主动发生什么

#### 保存规则

- 回顾按需生成，不预先制造空记录。
- 未确认草稿随原始数据变化而更新。
- 用户确认后保存为该周期历史快照。
- 下一阶段选择可以从愿望清单进入近期，但不自动制造任务。

### 6.10 可选模板

近期、愿望、旅行、体验、人际和回顾属于核心能力，默认启用。家庭结构和长期兴趣通过模板扩展。

| 模板 | 专属内容 | 不改变的通用数据 |
|---|---|---|
| **家庭事务** | 家务、维修、证件和家庭计划 | 任务、人物、日期和支出仍使用通用来源 |
| **亲子记录** | 成长事件、学校事项和重要日期 | 人物、体验和生活回顾仍是通用内容 |
| **宠物** | 健康、护理和日常生活记录 | 任务、健康事件和支出按对应板块关联 |
| **兴趣收藏** | 长期爱好、收藏清单和相关活动 | 愿望、体验和支出仍使用通用来源 |

模板沿用共同规则：新用户默认关闭；点击页头 `模板 · N` 启用或关闭；关闭只隐藏专属入口和字段，不删除历史数据。

### 6.11 与其他板块的边界

| 场景 | 主记录位置 | 跨板块处理 |
|---|---|---|
| 旅行、娱乐体验、私人相聚和愿望 | 生活 | 作为生活经历与关系的唯一来源 |
| 读书和学习过程 | 知识 | 生活可以引用由阅读带来的体验，不重复建立书籍记录 |
| 运动和身体数据 | 健康 | 旅行或活动可以引用运动事实，生活保留体验语义 |
| 旅行、娱乐、家庭等支出 | 财务 | 生活项目引用实际流水，不另记金额 |
| 工作关系和职业事件 | 工作 | 私人关系与相聚进入生活；同一人物身份只保留一份并按场景关联 |

### 6.12 现有功能的归位

| 现有功能 | 新位置或调整 |
|---|---|
| Life at a glance | 改为“近期”，移除旅行、娱乐、人物和愿望数量大盘 |
| People | 改为稳定人物档案与联系记录，不再按日志标题分组 |
| 全局 60 天未联系提醒 | 删除；改为每个人独立、由用户主动设置的联系节奏 |
| Trips | 进入“旅行”，使用想去 / 计划中 / 进行中 / 已完成 / 已取消状态 |
| Seen | 扩展为“体验记录”，覆盖娱乐与日常体验 |
| Dates ahead | 重要日期归入人物或关系；近期页与日历展示下一次发生时间 |
| Want to do | 改为愿望体系，不再把无日期愿望直接当普通任务 |
| Other / 未归领域日志 | 统一实施时让用户确认类型，不继续形成永久杂物区 |
| Recent | 近期只展示最近体验；完整记录进入旅行、体验或人际专页 |

### 6.13 明确不做

- 不把生活板块变成无法分类内容的永久“其他”收件箱。
- 不用旅行次数、娱乐数量、联系人数量或愿望完成率评价生活质量。
- 不把愿望自动变成任务、截止日期和逾期压力。
- 不用统一联系频率评价所有关系。
- 不生成亲密度、关系健康分和联系人排行榜。
- 不在旅行、体验和财务中重复保存同一笔实际支出。
- 不在知识与生活中重复建立书籍历史。
- 不做完整照片管理器、影视数据库和地点点评平台。
- 不因关闭模板删除家庭、亲子、宠物或兴趣历史。

### 6.14 产品验收标准

- 用户打开生活板块即可看到未来 30 天安排、本月主动选择、需要联系的人和最近体验。
- 愿望默认没有截止日期，不会自动逾期；只有用户主动选择后才进入近期或计划。
- 一条愿望转成旅行或体验计划后保留关联，不产生两份来源数据。
- 旅行能够保存计划、行程、同行人和回忆，并引用财务支出而不重复记账。
- 体验记录最少用一句话即可保存，并可关联人物、愿望、计划和旅行。
- 同一个人物拥有稳定档案；不同称呼不会静默创建多个关系对象。
- 只有设置了联系节奏的人会触发联系提醒；没有设置的人不显示逾期。
- 生日和纪念日每年滚动，完成提醒不会删除稳定日期。
- 生活回顾能自动归集事实，人工确认后保存月度或年度快照。
- 启用模板后出现对应专属入口；关闭模板后历史数据仍完整可恢复。

## 7. UI 设计与统一实施交接

五个板块全部封版后，先完成 UI 设计，再统一实施代码。

### 7.1 UI 设计输入

UI 设计以本文档为产品语义来源。优先完成：

- 五个板块的默认页
- 二级导航和页面切换
- 高频记录入口
- 新建和编辑表单
- 详情页、侧边面板或弹层
- 有数据和无数据状态
- 模板启用和关闭后的变化

原型使用接近真实的示例数据，不只使用占位符，确保页面能够暴露指标口径、极端长度和数据缺失问题。

### 7.2 设计视口

- 主要设计和验收视口：1440 × 960。
- 大屏补充视口：1920 × 1080。
- 390 px 只做次要回归，不作为 PC 桌面应用的主要布局依据。

### 7.3 UI 审查闸门

UI 完成后，先逐页核对：

- 页面是否覆盖本文档的核心问题
- 高频入口是否足够直接
- 同一事实是否被要求重复录入
- 指标是否有明确时间范围、单位和计算来源
- 模板关闭后核心能力是否仍然完整
- 无数据、数据缺失和历史迁移状态是否有合理表达
- 交互能否在现有 Tauri、React 和本地 IndexedDB 架构下实现

审查修订并确认后，才进入跨板块数据模型、旧数据迁移、公共组件和业务代码的统一实施。
