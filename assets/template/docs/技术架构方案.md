# 人生看板 · 技术架构方案

> **状态**：已确认 · 2026-08-11
> **核心约束**：①桌面端已定 Tauri+React、刚起步 ②移动端要最大化代码共享 ③学习成本权重极高 ④需要云同步多设备

## 一、总体架构：一套技术栈打三端

```
┌─────────────────────────────────────────────────┐
│              共享层 (shared/ - TypeScript)         │
│   数据模型 · 类型定义 · 业务逻辑 · 同步引擎 · API    │
└──────────┬──────────────────────┬────────────────┘
           │                      │
     ┌─────┴──────┐        ┌──────┴───────┐
     │  桌面端      │        │  移动端       │
     │  Tauri 2    │        │  React Native │
     │  + React    │        │  + Expo       │
     │  (macOS)    │        │  (iOS/Android)│
     └─────┬──────┘        └──────┬───────┘
           │                      │
     ┌─────┴──────┐        ┌──────┴───────┐
     │ SQLite     │        │ SQLite        │
     │ (本地)      │        │ (本地)         │
     └─────┬──────┘        └──────┬───────┘
           │                      │
           └──────────┬───────────┘
                      │
              ┌───────┴────────┐
              │   Supabase     │  ← 云同步后端
              │  (PostgreSQL)  │
              └────────────────┘
```

**一句话总结**：桌面用 Tauri+React，移动用 React Native+Expo，两端共享同一套 TypeScript 业务逻辑和数据模型，数据本地存 SQLite、云端用 Supabase 同步。

## 二、各平台具体推荐

### 1. Mac 桌面端：Tauri 2 + React + TypeScript（沿用已定方案）

| 项目 | 选择 | 理由 |
|---|---|---|
| 框架 | Tauri 2.0 | 已定；打包体积小，性能好，原生集成能力强 |
| UI | React 18 + TypeScript | 与移动端共享技能 |
| 本地数据库 | SQLite（通过 Tauri 的 SQL 插件） | 比 IndexedDB 更适合做同步；结构化查询；可跨端统一 |
| 状态管理 | Zustand + React Query | 轻量、易学、React/RN 通用 |

### 2. iOS + Android：React Native + Expo（一套代码两端运行）

**为什么不是 Flutter？** → 要学 Dart（新语言），且和桌面 React 完全不共享。
**为什么不是原生？** → 要学 Swift + Kotlin 两门语言，维护两套代码。
**为什么不是 Tauri Mobile？** → 理论共享最多，但移动端尚不成熟，从零起步踩坑没人帮，学习资料也少。React Native 资源最多，最适合入门。

| 项目 | 选择 | 理由 |
|---|---|---|
| 框架 | React Native + **Expo**（强烈推荐用 Expo） | Expo 免配置 iOS/Android 原生工程，一条命令出包，对新手极其友好 |
| UI 组件 | React Native Paper / NativeWind | 成熟组件库，快速搭界面 |
| 本地数据库 | expo-sqlite 或 WatermelonDB | 与桌面端 SQLite schema 对齐 |
| 导航 | Expo Router | 官方推荐，文件式路由，简单 |

### 3. 后端 & 云同步：Supabase（不自建后端）

要云同步且技术不熟的情况下，**强烈不建议自己写后端**。Supabase 提供开箱即用的：

- **PostgreSQL 数据库**（PRD 里复杂的跨板块数据关系，关系型数据库正合适）
- **用户认证**（邮箱 / 手机 / 第三方登录）
- **实时订阅**（多设备数据变更自动推送）
- **离线优先 + 同步**：配合本地 SQLite，设备离线写入本地，联网后同步到云端
- **行级权限**（RLS）：保证每个用户只能访问自己的数据
- 免费额度足够个人项目起步

> 备选：如果更看重「纯本地优先 + 自动冲突合并」，可考虑 PowerSync / ElectricSQL 这类 SQLite↔Postgres 同步引擎，但学习成本更高，不推荐作为起步。

## 三、代码共享结构（Monorepo）

用 **pnpm workspaces + Turborepo** 管理一个 monorepo，最大化复用：

```
life-board/
├── apps/
│   ├── desktop/          ← Tauri + React（Mac 桌面端）
│   └── mobile/           ← React Native + Expo（iOS/Android）
├── packages/
│   ├── shared/           ← 核心！两端 100% 共享
│   │   ├── db/           ← SQLite schema、迁移、查询（两端通用）
│   │   ├── models/       ← 工作记录、项目、收支流水... 类型定义
│   │   ├── sync/         ← Supabase 同步引擎
│   │   └── logic/        ← 周报归集、净资产计算等业务逻辑
│   └── ui/               ← 可共享的纯逻辑组件（非 DOM/RN 组件）
└── supabase/             ← 数据库 schema + RLS 策略
```

**共享比例预估**：数据模型、类型、业务逻辑、同步引擎可共享 **70%+**；只有 UI 渲染层（React DOM vs React Native）需要各写一套。

## 四、需要学的技术清单（尽量精简）

| 技术 | 用在哪 | 优先级 |
|---|---|---|
| **TypeScript** | 全局基础 | 🔴 必学 |
| **React** | 桌面 + 移动通用 | 🔴 必学 |
| **React Native + Expo** | 移动端 UI | 🔴 做移动端必学 |
| **Tauri** | 桌面端打包 / 系统能力 | 🟡 用到再查 |
| **SQL + SQLite** | 本地数据 | 🔴 必学 |
| **Supabase** | 后端 / 同步 | 🟡 平台托管，学基础操作 |
| Zustand / React Query | 状态管理 | 🟡 中期引入 |

> 好消息：React 和 TypeScript 是桌面和移动**通用**的，学一次两边都能用。所以真正要「新学」的只有 React Native（移动 UI 层）+ SQL 基础。

## 五、起步建议路径

1. **先做桌面端 MVP**（Tauri + React）：选 1 个板块（建议「工作」）跑通「记录 → 存储 → 列表 → 复盘」全链路
2. **接入 Supabase**：实现账号 + 数据云端存储
3. **抽取 shared 包**：把数据模型和逻辑移到 `packages/shared`
4. **起移动端**（Expo）：复用 shared 包，用 React Native 重写 UI
5. **实现本地 SQLite + 离线同步**：桌面和移动各自本地读写，联网同步 Supabase

---

## 六、不推荐 / 避坑

- ❌ **Electron**：体积大、内存高，相比 Tauri 对本项目无优势
- ❌ **Flutter**：体验好但要学 Dart，和桌面 React 完全割裂，违背「最大化共享」
- ❌ **双原生（Swift + Kotlin）**：体验最好但要学两门语言、维护两套代码，对新手不现实
- ❌ **自建后端**：技术不熟的情况下，自建 Node / Go 后端会拖慢进度，Supabase 足够

## 附录 · 决策依据

| 决策点 | 选择 | 关键理由 |
|---|---|---|
| 桌面端框架 | Tauri 2 + React | PRD 已定；体积小、性能好 |
| 移动端框架 | React Native + Expo | 与桌面共享 React/TS；生态成熟、入门资源多 |
| 跨端方案选型 | 排除 Flutter / 原生 / Tauri Mobile | 学习成本 + 代码共享最大化 |
| 后端 | Supabase | 不自建后端；开箱即用同步 + 认证 |
| 本地数据库 | SQLite（替代 PRD 原定的 IndexedDB） | 结构化、可同步、跨端统一 |
| 代码组织 | pnpm + Turborepo monorepo | shared 包共享 70%+ 业务逻辑 |
