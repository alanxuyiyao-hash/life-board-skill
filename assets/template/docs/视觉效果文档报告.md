# Part A · 现状设计规范

## 1. 产品与设计理念

### 1.1 产品定位

Life Board 是一款**纯本地**的桌面人生管理应用：把年度目标与每天的项目、任务、日志、读数、笔记、收支放进同一套系统，覆盖**工作 / 知识 / 健康 / 财务 / 生活**五个板块。所有数据只存在本机 IndexedDB，无账号、无云同步，备份走 JSON 导入导出。

视觉层面要服务的核心命题是：**把目标和日常连起来，且让用户长期愿意每天打开它**。这决定了它不能是冷冰冰的数据后台，也不能是花哨的玩具——它需要一种「有温度、可长期凝视」的视觉气质。

### 1.2 设计语言：「暖纸白底 + 现代看板感」

项目采用一套高度自洽的设计语言，可概括为两句话：

> **暖纸白底托底，深林绿点睛；层级靠边框不靠阴影，色彩靠身份不靠换肤。**

这套语言对标 **Notion / Things 3 / Linear / Apple Health**（见设计稿 `docs/superpowers/specs/2026-08-10-dashboard-modern-visual-design.md:18-25`），并提炼出五条可迁移规律，全部已落地：

| 规律 | 来源 | 在 Life Board 的体现 |
|---|---|---|
| **4 级暖灰墨阶，层次靠 tone 不靠 size 跳** | Things + Linear | `--ref-ink-1/2/3/4` 四档（见 §3） |
| **卡片靠边框 + 背景托起，投影只留给 1–2 个 hero 元素** | Linear + Notion | 默认卡无边框外阴影，仅 hero 卡用 `--ref-shadow-hero` |
| **大数字负字距 + tabular-nums + 下方 muted 单位** | Apple Health + Linear | KPI 数值 `letter-spacing:-.025em` + `tabular-nums` |
| **主色稀缺；类别身份色——每板块一个稳定 hue，色即图例** | Linear + Things | 五板块身份色数据驱动注入（见 §2.4） |
| **图表卫生——淡网格、单一主色系列、面积填充、圆角柱顶** | Linear + Notion | TrendChart 加 area path + 3 条淡网格 |

### 1.3 设计纪律的代码体现

这套语言不只是「画得像」，而是通过**代码约束**强制落地：

1. **三族 token 分工，禁止跨族混用**——`boards.css:1-14` 顶部注释明确规定：新增表面「配色只用 `--el-*` / `--nc-*`」，禁用 `--ink/--surface/--accent` 这类「会随深色翻转」的 token，原因是深色系统下浅色字会落在白卡上看不见。
2. **圆角是「唯一真相，勿再写字面值」**——`styles.css:94-102` 的注释明确要求所有圆角引用 `--r-*` token，历史上散落的 7/9/10/11/13/14/15/20/24px 字面值已全部归并。
3. **投影禁纯黑、禁高透明**——所有阴影色统一用主色低透明混合 `rgba(36,58,45,...)` 或 `rgba(20,20,19,...)`，而非纯黑 `rgba(0,0,0,...)`。

### 2.2 4 级暖灰墨阶（`refined.css` 设计稿定义）

层次靠 tone 不靠 size——这是 Things/Linear 流派的标志。四档墨阶把信息按重要性分层，避免「全部一个字号、靠加粗区分」的粗糙感：

| 级别 | Token | HEX | 语义 |
|---|---|---|---|
| ink-1 | `--ref-ink-1` | `#1b1c1a` | 主标题 / 数值 |
| ink-2 | `--ref-ink-2` | `#3d3c36` | 次要正文 |
| ink-3 | `--ref-ink-3` | `#66645d` | 说明文字（= 旧 `--ref-muted`）|
| ink-4 | `--ref-ink-4` | `#9a978d` | 辅助 / 占位 |

> 兼容策略：保留 `--ref-ink` / `--ref-muted` / `--ref-ink-soft` 别名指向新值，全站自动跟随，不必逐处替换（设计稿 `:46`）。

另外还有一组 el 皮肤暖灰：`--el-ink #1b1c1a` → `--el-mut-ink #4b4a44` → `--el-mut-strong #605e57` → `--el-muted #8a887f` → `--el-mut2 #b5b2a8`（5 档）。

### 2.4 五板块身份色（数据驱动，非 CSS class）

这是整个色彩系统最有特色的设计决策。**板块是「数据不是代码」**（PRD §2），每个 Area 实体自带 `color`（HEX）和 `icon`（emoji）字段。五个内置板块的种子默认色（`src/lib/seed.ts:24-32`）：

| 板块 | emoji | 身份色 | 设计意图 |
|---|---|---|---|
| 💼 工作 Work | 💼 | `#b5791a` 琥珀 | 沿用阶段色 amber |
| 📚 知识 Knowledge | 📚 | `#5a6ea0` 沉静蓝 | 补一支沉静蓝，与主色区分 |
| 🌿 健康 Health | 🌿 | `#2c7a4e` 绿 | 复用 `--good` 绿 |
| 💰 财务 Finance | 💰 | `#14422b` 深林绿 | 主色，强调财务是核心 |
| 🧭 生活 Life | 🧭 | `#c0564d` 砖红 | 复用 rose |

**身份色怎么用进 UI**——关键在于「色即图例」，不在 CSS 里硬编码：

1. **总览板块卡**：每个板块一张 KpiCard，左上 `area.color` 小圆点 + 板块名，数值也染成板块色（`OverviewRefined.tsx:213-226`，`color={area.color}`）。
2. **任务/活动流圆点**：`<span className="ref-task-dot" style={{ background: area.color }}>`（`OverviewRefined.tsx:90`）。
3. **hero 卡左色条**：通过 `--ref-tone-color` 注入，`.ref-kpi-card--hero::before` 画 5px 宽左竖条（`refined.css:540-546`）。
4. **图表折线/面积/端点**：TrendChart 接受 `tone` prop，CSS 变量 `--tone` 驱动颜色，用户改了板块色图表自动跟随。

好处是：①用户在结构设置改板块色，全站图表/卡片自动跟随；②五板块不会「各自换肤」变成「小 app 拼盘」（PRD §5.3 明确警告要防止拼盘感）。

另有 8 组暖调低饱和「项目头像」色对（`src/lib/avatar.ts:14-23`：clay/sage/mauve/sand/stone/slate-warm/taupe/blush-neutral），按 id 稳定哈希分配，明确不与语义色冲突。

### 2.5 深色模式

- **只跟随系统，无手动切换开关**（`@media (prefers-color-scheme: dark)`，`styles.css:208-232`）。
- **只翻颜色 token，几何/字阶不动**——深色下圆角、间距、字号完全不变。
- 深色是「暖炭底配暖米白字」：`--bg #181715`、`--ink #f1eee8`、`--muted #a39e95`、`--line #38352f`。
- 主色在深底上提亮：`--accent #2f6247`、`--good #7cc79b`、`--danger #ffb4a9`、`--warn #f0a85a`。
- 反色 chip 翻成「亮片 + 深字」：`--ink-surface #a1d2b2`（薄荷）、`--on-ink #002111`。

> ⚠️ **关键约束**：`--el-*` 皮肤色板**字面值不随深色翻转**（`styles.css:150`、`boards.css:10-13` 明确声明），页面内容整体保持浅色皮肤。也就是说深色模式主要影响应用壳层（侧栏/顶栏/底色），内容卡片仍是白底。

## 3. 字体排版

### 3.1 四字族协作 + CJK 字体根因修复

这是项目最见功力的一处。**自托管 woff2**，放在 `public/fonts/`，`index.html:19-21` 预加载首屏关键字重。四个字族各司其职：

| 字族 | 角色 | 字重 | 覆盖范围 |
|---|---|---|---|
| **Noto Sans SC（思源黑体）** | 中英统一字族 | 400 / 700（子集 ~1500 字） | CJK 主力 |
| **Hanken Grotesk** | 拉丁正文主用（可变字重） | 100–900 var | 拉丁 |
| **Clash Display** | 展示/标题 | 500 / 600 / 700 | 仅拉丁 |
| **General Sans** | UI 控件 | 400 / 500 / 600 | 仅拉丁 |

**CJK 字体根因修复**（设计稿 `:16, 91-93`）：原本 `--ref-display` 用 Clash Display 扛标题，但 Clash Display **只覆盖拉丁字母**，所有中文回落到 PingFang SC，两种字体风格不统一——这是用户反馈「字体不好看」的直接根因。修复方式：CJK 优先 `'PingFang SC'`（macOS）/ `'HarmonyOS Sans SC'`（Win），与 Hanken Grotesk 几何感协调，**零新增字体文件**。

字体栈定义（`styles.css` + `refined.css:43-49`）：

```css
--ref-display: 'Noto Sans SC', 'Clash Display', 'Hanken Grotesk',
               -apple-system, 'SF Pro Display', system-ui,
               'PingFang SC', 'HarmonyOS Sans SC', 'Microsoft YaHei', sans-serif;
--ref-ui:      'Noto Sans SC', 'General Sans', 'Hanken Grotesk', ...;
```

### 3.2 字阶

| 用途 | 规格 |
|---|---|
| 页面 h1 | `600 22px/1.2`，`letter-spacing -0.015em` |
| display-xl（28px+ 标题） | `letter-spacing -.02em` |
| section h2 | `600 18px/1.2` |
| KPI 数值（hero） | `600 27px/1`，`tabular-nums` |
| 正文 strong | `500 14px/1.35` |
| 次要文字 | `400 13px/1.35` |
| 辅助 | `400 12px/1.4` |
| eyebrow 微标 | `500 11px`，`letter-spacing 0.08em`，`uppercase` |
| 通用 token | `--fs-cardtitle 15.5px`、`--fs-meta 12.5px` |

### 3.3 数字排版纪律

- **`font-variant-numeric: tabular-nums lining-nums`** 全站强制，保证数字对齐（金额、读数、KPI）。
- **负字距**：标题 `-0.015em`、KPI 大数值 `-0.025em`、display-xl `-.02em`——Linear 标志性处理。
- **货币符号微调** `.cur-sym`：`margin-right:0.5px`，修 Clash Display 的 ¥ 横笔伸进下一字符。
- **隐藏金额** `.money-hidden`：`color:var(--muted); letter-spacing:0.08em`，遮成 `¥•••` 保留正负方向。

## 4. 设计 Token

所有 token 集中在 `:root`，是「唯一真相源」。

### 4.1 圆角（5 档 + pill）

`styles.css:94-102`，注释明确「唯一真相，勿再写字面值」：

| Token | 值 | 用途 |
|---|---|---|
| `--r-badge` | `8px` | 小角标 |
| `--r-card` | `12px` | 卡片/行 |
| `--r-md` | `16px` | 中等容器 |
| `--r-panel` | `18px` | 面板 |
| `--r-lg` | `22px` | 大面板/Sheet 顶 |
| `--r-pill` | `999px` | 胶囊 |

另有新卡片基调 `--nc-r: 12px` / `--nc-r-sm: 8px` / `--nc-r-xs: 6px`。

### 4.2 阴影：hairline 哲学

这是整个设计系统**最核心的视觉决策**。参考 Linear/Vercel/Raycast/Anthropic，**层级靠 1px hairline 边框而非阴影**（`styles.css:186-200`）。边框用主色低透明混合，三档强度：

```css
--nc-border-subtle: color-mix(in srgb, #14422b 6%,  #fbf9f5);
--nc-border:        color-mix(in srgb, #14422b 10%, #fbf9f5);
--nc-border-strong: color-mix(in srgb, #14422b 18%, #fbf9f5);  /* hover/选中 */
```

阴影被刻意稀缺化，分三档 + hero + modal：

| Token | 值 | 用途 |
|---|---|---|
| `--sh-card` | `0 1px 2px rgba(36,58,45,0.05)` | 极轻接触影 |
| `--sh-float` | `0 8px 24px rgba(36,58,45,0.12), 0 2px 6px rgba(36,58,45,0.06)` | 悬浮元素 |
| `--sh-pop` | `0 2px 6px rgba(36,58,45,0.3)` | 弹出层 |
| `--ref-shadow-hero` | `0 1px 2px rgba(20,20,19,.05), 0 8px 24px -10px rgba(20,20,19,.14)` | **唯一**给焦点卡的投影 |
| `--nc-shadow-modal` | `0 24px 64px -16px rgba(20,20,19,.28), 0 0 0 1px var(--nc-border)` | 模态框 |

> 设计原则（设计稿 `:77-79`）：**默认卡 = 边框 + 无投影**，投影改为 opt-in，只给每屏 1–2 个 hero 元素（如财务「现金净变化」KPI、Health 主趋势图）。

### 4.3 间距（4px 基线）

`styles.css:113-123`：`--sp-1 4px` … `--sp-6 24px`；`--pad-screen 16px`；`--gap-card 10px`；`--gap-tight 6px`；新卡片基调 `--nc-pad 20px` / `--nc-pad-compact 16px` / `--nc-gap 12px` / `--nc-gap-grid 16px`；页面左右内边距 `--ref-page-pad-x 26px`（大屏 1600px+ 加宽到 32px）。

### 4.4 按压缩放

两档（`styles.css`）：`--press-sm: 0.94`（图标钮/chip/FAB）、`--press-lg: 0.98`（卡片/行）。少数写死值：tab `0.92`、big-btn `0.96`。提供即时触觉反馈。

## 5. 布局与信息架构

### 5.1 窗口与外壳

- **Tauri 单窗口**，`1280×820`，`minWidth 960 / minHeight 640`，可调整大小（`src-tauri/tauri.conf.json`）。
- **使用系统原生标题栏**（未自定义），Rust 端是最简 `tauri::Builder`。
- 桌面端实际**没有顶栏**——`.topbar` 在 `.ref-app` 下 `display:none`（`refined.css:1688`），搜索/记录/头像全部下沉到侧栏。

### 5.2 桌面侧栏布局（≥960px，`refined.css:1698`）

```
┌─────────────┬──────────────────────────────────┐
│  .tabbar    │  .content (唯一滚动容器)          │
│  222px      │  ┌────────────────────────────┐  │
│  可折叠 ⌘B   │  │ .ref-page__body (各页滚动)  │  │
│             │  │  RefinedPage 壳 + tabs      │  │
│  品牌+搜索   │  │  KpiGrid / List / Grid ...  │  │
│  总览/日历   │  └────────────────────────────┘  │
│  五板块      │                                  │
│  设置        │                                  │
│  记录⌘N+头像 │                                  │
└─────────────┴──────────────────────────────────┘
```

- `.tabbar` 固定宽 222px（`flex: 0 0 222px`），`.content` 占剩余。
- 侧栏可折叠（`sidebarCollapsed` 状态，持久化 localStorage，⌘B 切换）。
- 主导航图标全内联 SVG（lucide 风描边，`App.tsx:153-237`）：总览=四宫格、日历、工作=公文包、知识=翻开书、健康=心电图、财务=钱包、生活=罗盘、设置=齿轮。

### 5.3 keep-alive 路由

- **无 react-router**，用 `useState<Tab>` + URL query 解析（`lib/refinedRouting.ts`）。
- **访问过的 tab 常驻不卸载**（`<div className="tab-panel" hidden={tab!==id}>`，`App.tsx:247-256, 450-464`），切回保留滚动/筛选/折叠态。每 tab 独立 `ErrorBoundary + Suspense`，崩溃自愈用 epoch key 整树 remount。
- 首访才 lazy import，保住 code-splitting。

### 5.4 五板块导航 + 子 tab

每个板块对应一个 `*Refined` 页面，内部还有子 tab（二级 tablist，roving tabindex 键盘导航）：

| 板块 | 子 tab |
|---|---|
| 工作 | week / log / projects / review / career / quotes / content |
| 知识 | now / log / books / courses / notes / review / exam / language / research |
| 健康 | now / training / metrics / events / profile / review（+ 5 模板 tab）|
| 财务 | month / flow / assets / invest / budget / review（+ 4 模板 tab）|
| 生活 | soon / wishes / trips / experiences / people / review |

### 5.5 移动端退化（<960px，PWA 残留）

同一前端也打 PWA，<960px 侧栏消失，`.tabbar` 变成屏幕底部居中浮动胶囊（`position:fixed; width:min(100%-24px,520px); height:66px`）。但因 Tauri 窗口 `minWidth 960`，**桌面打包运行时永远 ≥960px**，移动分支实际只服务于 web 预览/PWA/demo。断点：1600/960/560/420/389/360。

| `MonthPicker.tsx` | **MonthPicker** |

### 6.2 卡片层级与 hero 焦点

- **Surface**（`Surfaces.tsx:4-16`）：通用卡容器，`variant: 'flat'|'raised'|'outlined'`，`padding: 'none'|'compact'|'normal'`。
- **默认卡 = 边框 + 无投影**（设计稿 `:77-79`），把投影从默认行为拿掉。
- **KpiCard hero 变体**：唯一应用 `--ref-shadow-hero`，加 `::before` 3–5px 左色条（`background: var(--tone, transparent)`），tone 为空时不显示。语义：每屏 1 个最重要的数/图。
- **SectionHeader**：章节标题 + 副标题 + 右侧 action。

### 6.3 tone 系统（核心设计语言）

`RefinedTone = 'neutral' | 'accent' | 'warning' | 'danger' | 'success'`（`types.ts:3`）。每个组件接受 `tone` prop，渲染成 `.ref-tone--{tone}`，CSS 注入 `--ref-tone-color` + `--ref-tone-bg` 两个子 token（`refined.css:629-647`）。KpiCard 还支持 `color` prop 注入任意颜色（板块色机制，`Surfaces.tsx:63-67`）。

### 6.4 KPI / 进度 / 图表

- **KpiCard**：大数字指标卡，hero 变体带专属投影，tone 着色。
- **ProgressRow**（`Surfaces.tsx:78-114`）：**线性进度条**，`role="progressbar" aria-valuemin/max/now`，track 内 `<span style={{width: percent%}}>`，`transition: width 220ms ease`。用于目标进度、预算完成率。
- **TrendChart**（`Charts.tsx:9-74`）：**手写 SVG 折线 + 面积填充**，3 条淡网格线，每点带 `<title>` tooltip，`role="img" aria-label`。升级后加 area path（`fill-opacity:.10`）、淡网格（`stroke:rgba(20,20,19,.05)`）、线宽收到 2.25、端点实心。
- **AllocationDonut**（`Charts.tsx:91-155`）：SVG 环形图（`viewBox 0 0 42 42`，`pathLength 100`），中心放数值/标签，配 `<figcaption>` 图例。
- **无第三方图表库**（package.json 无 recharts/d3/chart.js），全部手写 SVG。

### 6.5 Sheet / Modal / Toast

- **Sheet**（`src/components/Sheet.tsx`，移动原生弹层风格）：半透明遮罩 + 顶部圆角浮卡从底部滑入（`slideup`），有拖拽把手 `.sheet-grip`、**指针下滑关闭**（阈值 90px）、Esc 关闭、⌘/Ctrl+Enter 提交。`role="dialog" aria-modal`。被 BoardRecordSheet/GoalSheet/LifeEntrySheet/ThreadSheet 等复用。
- **Modal**（`refined/Modal.tsx`，桌面风格）：居中浮卡（small/medium/large），自己实现 Tab 焦点陷阱（`trapFocus`），打开聚焦首个可聚焦元素、关闭还焦点。`role="dialog" aria-modal aria-labelledby/describedby`。
- **ConfirmDialog**：`role="alertdialog"`，默认聚焦「取消」，危险操作柔玫瑰色，`createPortal` 到 body。
- **Toast**（`Toast.tsx`）：模块级发布订阅，`role="status" aria-live="polite"`，带撤销动作（撤销类停 5s，普通 2.2s），`toast-in` 动画 `translateY(16px) scale(0.96)` 淡入。

### 6.6 空状态 / 加载态

- **两套 EmptyState**：`components/EmptyState.tsx`（细线 icon + 标题 + hint + 主操作胶囊）和 `refined/Feedback.tsx`（`ref-` 命名空间）。各页空态都带「记录工作 / 新建项目」等一键起步 CTA。

- **RefinedReadySignal**：等字体加载 + spinner 消失后给 `<html>` 打 `data-refined-ready`，供截图/视觉回归契约用。

# Part B · 专业评估

## 1. 视觉优点

### 1.1 设计语言高度自洽，有清晰的「为什么」

最难得的一点：这不是一堆「看起来不错」的样式堆砌，而是**有明确对标、有取舍依据、有代码约束**的设计系统。

- 五条对标规律（Things/Linear/Notion/Apple Health）全部落地，且每条都能在 token 和组件里找到对应物。
- 设计纪律用代码强制（三族 token 分工、圆角唯一真相、投影禁纯黑）——这意味着新人改样式时，约束本身会防止他们破坏一致性。
- 有一份 2026-08-10 的内部视觉设计稿完整记录了「为什么这么改」，这是极少见的工程化设计文档实践。

### 1.2 token 纪律严明

- 单一真相源（`:root`），别名兼容（`--ref-ink`/`--ref-muted` 指向新 ink-1/3），全站自动跟随。
- 圆角/间距/阴影都有明确档位和禁令，避免「7px、9px、10px、11px 全都用」的熵增。
- 用 `color-mix(in srgb, 主色 N%, 底色)` 生成边框三档强度，比硬编码灰值更能在深色/换肤时保持协调。

### 1.3 a11y 实践扎实，远超一般桌面应用

这是本项目最突出的工程亮点之一：

- **语义角色齐全**：dialog/alertdialog/status/tablist/tab/tabpanel/progressbar/listbox/option/menu/menuitem/switch/region/img，几乎覆盖所有交互模式。
- **roving tabindex 键盘导航**：二级 tab 用箭头键/Home/End，跳过 disabled，**有单元测试**（`keyboardNavigation.test.ts`）。
- **焦点管理**：`useFocusTrap` hook，打开移入、Tab 内循环、关闭还焦点。
- **`:focus-visible` 焦点环**（`refined.css:68-74`，3px 半透明 accent + offset 2px）。
- **40px 命中区**、不锁缩放（WCAG 1.4.4）、装饰 SVG `aria-hidden`、图表 `role="img" + aria-label`。
- **reduced-motion 双保险**（全局 + 13 处组件级 + JS 层）。

### 1.4 板块色「数据驱动」而非「CSS class」

五板块身份色通过 `area.color` 字段 + CSS 变量 `--tone` 注入，用户改色全站自动跟随。这比「每个板块一套 `.work-*` `.health-*` class」优雅得多，也天然防止了「小 app 拼盘」——所有板块共用一套组件，只是换了身份色。

### 1.5 CJK 字体根因修复到位

准确诊断了「字体不好看」的真因（Clash Display 不覆盖 CJK → 回落 PingFang 风格不统一），用系统字体（PingFang SC / HarmonyOS Sans）+ Noto Sans SC 子集解决，零新增字体文件，同时自托管拉丁字体保证离线可用。

### 1.6 层级靠边框不靠阴影的克制

默认卡无边框外阴影，投影只留给 hero——这让信息密集的看板不会「一片阴影糊在一起」，视觉噪音极低。这是 Linear 流派的精髓，落地得很干净。

### 1.7 本地优先与隐私的视觉呼应

隐藏金额 `.money-hidden` 保留正负方向（不只是变成星号）、纯本地无云同步、备份走 JSON——这些产品决策和「暖纸白底、可长期凝视」的气质是一致的，应用不像 SaaS 后台，更像一本私人手账。

## 2. 发现的问题

### 2.1 一致性问题

**P1 · 三套 CSS 文件 + 命名空间混杂，认知负担高**
`styles.css`（巨大，超 256KB 读上限）/ `boards.css` / `refined.css` 三文件，加上 `--el-*` / `--nc-*` / `--ref-*` 三族 token + 大量历史类名（`he-*` `cal-el-*` `pd-*` `dp-*` `qc-*` `me-*` `oh-*` `ad-*` `recv-*` `swipe-*` `net-*`）。新贡献者要判断「该用哪族 token、哪个命名空间」需要读 `boards.css:1-14` 的约束注释，门槛不低。建议补一份「token 与命名空间速查表」进项目文档。

**P2 · 旧版页面与 Refined 版页面并存**
`pages/` 下成对存在 `Work.tsx` / `WorkRefined.tsx` 等（旧版仅参与 TS 编译作兼容，App.tsx 实际只用 Refined 版）。这会让代码搜索和阅读产生混淆，也增加 bundle 体积分析的心智成本。建议择机移除旧版或明确标注「deprecated，勿改」。

**P2 · package.json name 仍是 `content-manager-desktop`**
历史遗留，与产品名 Life Board 不符，会让新人困惑。建议改名。

### 2.2 可访问性残点

**P2 · 少量装饰性裸字符而非 icon + aria-label**
侧栏 brand 的 `‹`/`L`、`⌕`、`×`、`i` 等是裸字符。虽然父按钮有 `aria-label` 兜底，但屏幕阅读器对裸字符的处理不一致，建议换成内联 SVG + `aria-hidden`。

**P3 · 深色模式下 `--el-*` 皮肤不翻转的潜在可读性风险**
深色模式只翻 `--bg/--surface/--accent` 等基础 token，`--el-*` 卡面色板保持浅色字面值。这在「暖炭底侧栏 + 白底内容卡」的预期下是 OK 的，但如果将来某处把 `--el-ink`（`#1b1c1a` 深字）用在了 `--bg`（深色下 `#181715`）背景上，就会深字落深底看不见。`boards.css:10-13` 的注释正是为防这个。建议在 CI 加一个 lint：禁止在非 `--el-card` 背景上使用 `--el-ink` 系文字色。**待核实**：是否真存在这样的误用。

### 2.3 性能问题

**P2 · `styles.css` 单文件巨大（>256KB）**
虽然 Vite 会 minify，但开发体验和首屏解析成本不理想。建议评估是否拆分（按板块或按组件族），或引入 CSS Modules / CSS-in-JS-lite（如 vanilla-extract）做按需加载。不过这是大改，需权衡。

**P3 · 自托管字体体积**
Clash Display（500/600/700）+ General Sans（400/500/600）+ Hanken Grotesk var + Noto SC 子集（400/700），合计 woff2 体积不小。已 preload 首屏三个，但建议加 `font-display: swap` 并审计实际使用的字重，移除未用字重。

### 2.4 桌面适配不彻底

**P2 · 移动布局分支在桌面运行时是死代码**
Tauri `minWidth 960`，移动分支（<960px 底部胶囊导航）在桌面永不触发，却仍被打包进去。这增加了 bundle 和维护成本。如果 PWA 路线已放弃，建议移除移动分支；如果保留，建议明确双形态策略文档。

**P3 · 未利用桌面宽屏（>1600px）**
目前大屏（≥1600px）只是把页面内边距从 26px 加宽到 32px，内容区仍是单列居中。对于 27"/32" 显示器，看板可以做成多列网格（如 Overview 三栏、Finance KPI + 流水并排）。**待核实**：是否与「聚焦、不分散」的产品理念冲突——可能是有意为之。

### 2.5 可维护性

**P2 · 无统一 `--ease` / `--duration` token**
动效在组件 CSS 里就近写（140ms ease / 100ms ease / 220ms ease / 0.35s ease 散布），虽然节奏一致，但没有 token 化。建议抽 `--ease-out` / `--dur-fast 100ms` / `--dur-base 140ms` / `--dur-slow 220ms`，便于全局调速。

**P3 · react-spring 仅一处使用，依赖成本与收益不匹配**
`@react-spring/web` 只用于 SwipeRow 的吸附回弹。如果 SwipeRow 是高频组件尚可，但若只在订单/列表项用，可以考虑用纯 CSS `transition + cubic-bezier` 替代，省一个依赖。**待核实**：SwipeRow 的实际使用频率。

## 3. 风险与隐患

### 3.1 单点 CSS 文件的「爆炸半径」

`styles.css` 单文件承载全部基础样式 + 历史组件皮肤。任何一处误改（尤其 `:root` token）会影响全站。虽然有 token 别名兜底，但缺乏自动化视觉回归（虽然有 `shot-desktop.mjs` 截图契约，但 37 个状态是否纳入 CI **待核实**）。

### 3.2 设计稿标注「本期不做」的项易被遗忘

设计稿 `:98-104` 明确排除了「趋势 delta（▲/▼ 环比）」，理由是需接 `momDelta` 数据流（`src/lib/contentStats.ts:91` 已存在）超出「只改样式」范围。这是合理的范围控制，但**这类「有意推迟」的项如果没有 issue 跟踪，容易被永久遗忘**。建议把它登记成 P1 后续任务。

### 3.3 深色模式无手动开关

只跟随系统，用户在「系统浅色 + 想要应用深色」（或反之）时无法切换。这是产品取舍（简化），但对长时间夜间使用的「人生管理」类应用，手动深色开关是常见期望。**建议**：在 Settings 加一个「外观：跟随系统 / 浅色 / 深色」三档（成本低，只需一个 `data-theme` attribute + 覆盖媒体查询）。

## 4. 改进建议（按优先级）

### P0（紧急，影响正确性/可用性）
- **无**。当前视觉系统在正确性上没有阻断性问题。

### P1（重要，影响一致性与完整度）

1. **落地「趋势 delta（▲/▼ 环比）」**——设计稿已标注、`momDelta` 数据已存在，是「现代看板感」最后一块拼图。接入每个 KPI，配 tone（正绿/负红/中性灰）。
2. **补「token 与命名空间速查表」文档**——讲清 `--el-*` / `--nc-*` / `--ref-*` 各自适用场景、三 CSS 文件职责边界、深色翻转规则。降低贡献门槛。
3. **Settings 加手动外观开关**——「跟随系统 / 浅色 / 深色」三档，配 `data-theme` attribute。

### P2（改进，提升体验与可维护性）

4. **抽动效 token**——`--ease-out` / `--dur-fast/base/slow`，全局调速。
5. **移除或明确标注旧版页面**——`Work.tsx` 等，减少混淆。
6. **审计深色 `--el-*` 误用**——加 CI lint 防止深字落深底。
7. **裸字符图标化**——侧栏 brand 的 `‹`/`L`/`⌓` 等换内联 SVG + `aria-hidden`。
8. **宽屏多列布局探索**——Overview/Finance 在 ≥1600px 做多列网格（需与「聚焦」理念权衡）。

### P3（打磨）

9. **字体体积审计**——移除未用字重，确认 `font-display: swap`。
10. **评估移除移动布局死代码**（若 PWA 路线已放弃）。
11. **评估用纯 CSS 替代 SwipeRow 的 react-spring**（若使用频率低）。
12. **package.json name 改为 life-board**。

## 总结

Life Board 的视觉系统是一个**工程化程度很高、设计意图清晰、a11y 扎实**的系统。它最大的优势不在于「好看」（虽然确实耐看），而在于**每个视觉决策都有据可查、有 token 约束、有对标参照**——这是很多「画得好看但难维护」的设计系统所欠缺的。

主要短板集中在**工程治理**层面（多文件多命名空间的认知负担、历史代码并存、单文件爆炸半径），而非视觉设计本身。Part B 的改进建议大多是「补全已规划但未做的项」（P1）和「工程治理优化」（P2/P3），不需要推翻现有设计语言。

**一句话评价**：这是一个克制、自律、可长期演进的视觉系统；下一步的重点应该是补全趋势 delta、降低贡献门槛、加固深色模式可控性，而非重做视觉。
